### 실행 중 발견·수정한 문제

1. **종료 시 코어 덤프**: Replicator 1.12가 `annotator.detach()`에 render product 경로를 요구 → 경로 전달로 수정. 이후 정상 종료(exit 0).
2. **PhysX 스키드 회전 불가**: `tools/physics_probe.py` 측정(명령 대비 실제 요 각속도 비율).

   | 바퀴 모델 | 직진 0.15m/s | 제자리 회전 좌/우 | 원호 주행 | 비고 |
   |---|---|---|---|---|
   | PhysX 실린더 | 0.150 | 0.43 / 0.13 | 0.18(불안정) | 회전 중 차체 25° 기울어 넘어짐 |
   | PhysX 구 | 0.150 | 0.40 / 0.40 | **0.03** | 마찰·토크·솔버 반복·축간 변경도 3–9% |
   | 운동학 스키드(η=0.6) | 0.150 | 0.60 / 0.60 | 0.60 | 수집·평가 기본값 |

   쿨롱 마찰 준정적 계산으로는 축간 14/좌우 13cm에서 회전 효율 약 0.46이므로 PhysX 원호 결과는 비물리적이다.
   수집·평가는 `kinematic_skid`(모터 편차·1차 지연·포화·η 무작위화), PhysX는 진단용으로 남겼다.
3. **교사 이탈**: η<1에서 pure pursuit가 바깥으로 밀리고, 18.5cm 가운데 도로의 90° 교차로에서 모서리를 깎음 →
   꼭짓점까지 직진 후 제자리 회전, 요 비율·좌우 모터 편차 온라인 보상, T자 회전점 2.5cm 안쪽 이동.
   오프라인 하네스와 Isaac 모두 수집 시드 40개(outer 30, inner 10)를 **이탈 0으로 완주**.
4. **카메라 불일치**: 기존 추정(높이 14cm, 15° 아래, 66°)이 차량 카메라 사진과 크게 달라 사진에서 다시 추정
   (높이 약 7cm, 8.5° 위, 중심 fx≈330px, k1≈-0.3, [사진 추정]). 왜곡 렌더링·라벨 변환(`dtwin/lens.py`), 방 배경·나무·
   색/블러 무작위화를 추가. 방향 표지판은 사진의 꺾인 화살표(↰ ↑ ↱)로, 꺼진 신호등 등은 어두운 색으로 변경(v3).

### 표지판 미션 진단 (차선 = 교사, 표지판·정지·교차로 = 카메라 검출기 + 바퀴 측정)

`run_sim.py --mode expert --teacher-lane-diagnostic --missions`로 미션 판단만 분리해 확인했다(자율주행 성공률과 별개).
발견·수정한 문제:

1. **바퀴 odometry 회전 과대**: 스키드 미끄러짐(η=0.6)을 모르는 이상적 차동 공식으로 첫 모서리에서 방향 오차 40° 이상 →
   위치가 틀어져 엉뚱한 교차로로 판단하고 이탈. 유효 좌우 간격 `odometry_track_width_m`(= 13cm/η, [추정])을 추가.
   실차에서는 `tools/motion_calibration.py`의 η 실측으로 정한다.
2. **바깥 T자에 방향 표지판 없음 → 무한 대기**: 녹음 03:44–03:50("모든 교차로에 방향 표시")에 맞춰 동·남·서 T자에 직진 표지판 추가.
3. **모서리 전 표지판 ↔ 모서리 뒤 분홍선**: 진행 방향만으로 분홍선을 찾다가 이미 선 앞에서 짝지어 기한 초과. 표지판을 1.2m
   주행 동안 보류하고, 표지판 위치에서 가장 가까운 분홍선과 짝지어 선의 법선 방향 거리로 판정.
4. **방향 표지판 오판**: 같은 표지판이 프레임마다 직진/우회전으로 갈라져 충돌. 방향 표지판을 한 추적으로 묶고 신뢰도 투표,
   교차로별로도 증거를 합산해 2/3 이상일 때만 요청.

결과(seed 7005, 120초): STOP을 보고 정지 후 재출발(미션 완료 1), 동쪽 T자에서 직진 표지판을 보고 직진 통과.
남쪽 T자에서 가까운 직진 표지판을 비스듬한 각도에서 계속 "우회전"으로 읽어(0.57–0.71) 증거가 갈려 **충돌로 안전 정지**.
경적·감속20·신호는 이 주행에서 아직 도달하지 못했다. 검출기의 비스듬한 각도 방향 표지판 구분이 남은 과제다.

A5는 학습 회차가 늘수록 실제 직선 오차는 줄고(0.204 → 0.186) 실제 커브 오차는 커져(0.33 → 0.41), 커브 기준 선택이
덜 학습된 1회차를 골랐다. 합성 validation으로 고른 A5b는 Isaac Sim 일반 두 바퀴 9/10이고, **합성만으로 실제 커브
곡률 0.64**(A 0.35, 사람 0.60)를 낸다. 교사 속도 55%라 두 바퀴 평가는 180초로 했다.

**가혹 조건 분해** (`--stress-parts`, seed 10000–10004, 90초, 이탈 0이고 3m 이상 주행 = 통과). 위치 정답을 쓰는 교사는
가혹 조건 전체에서 5/5(원래 속도·55% 모두)라, 실패는 카메라 정책의 한계다.

| 켠 조건 | A5b 통과 |
|---|---|
| 지연 3프레임 | 5/5 |
| 밝기 0.55/1.5배 + 잡음 9 | 4/5 |
| 좌우 모터 0.75/1.2 | 4/5 |
| 반사(거칠기 0.08) | 3/5 |
| 카메라 기울기 ±8° | 3/5 |
| 회전 효율 0.30 + 모터 시정수 0.195초 | **1/5** |
| 모터 차이 제외 5개 동시 | 0/5 (A도 0/5) |

실패 거리는 거의 0.7–1.0m로, 출발점에서 첫 모서리 커브가 시작되는 거리다. 조건이 나빠지면 첫 커브를 못 돈다.
가장 큰 요인은 회전 효율 저하로, 학습 범위(η 0.33–0.55, 실측 0.43)보다 낮은 0.30이다. 사진 한 장만 보는 정책은
차가 덜 도는지 알 수 없어 보정하지 못한다. 실차와 직접 관련된 반사·카메라 각도도 단독으로 2/5씩 실패시킨다.

A는 Isaac Sim 일반 평가 outer 10/10 두 바퀴(이탈 0 9회)였지만 가혹 조건(밝기 0.55/1.5배, 강한 반사, 좌우 모터 차이,
카메라 ±8°) 5/5가 1m 안에 이탈했다. 깨끗한 합성 장면에만 맞은 모델이 실차에서 실패한 것과 같은 양상이다.
A는 합성 교사 습관대로 전진 0.97–0.99를 내어 같은 설정에서 B의 약 2배 속도로 달렸다.

촬영→모터 지연 p50 34–38 ms, p95 44–53 ms. **전원**: 다른 사용자 프로세스가 Pi CPU를 2.5코어 이상 쓰는 동안
(대기 84–86°C) 모터 시작 수 초 안에 Pi가 4회 꺼졌다(`throttled` 전압 부족 비트). 그 프로세스가 끝나고 47–60°C에서
시작한 주행은 180초를 버텼다. Pi 팬은 인식되지 않는다. 원본 영상·기록은 공개 제외.

트랙 실측(2026-10-31) 반영: 동쪽 바깥 도로만 24cm(나머지 26cm), 가운데 도로 18/21cm, 바깥 모서리 반경 32cm.
`make_track.py`에서 동쪽 도로 폭과 동쪽 초록 띠(추정 +2cm)만 바뀌었고 다른 좌표는 그대로다.

### RTX에서 남은 확인 (2026-10-22 기준)

1. `--check`로 Ubuntu·드라이버·VRAM·설치 버전 기록.
2. 수동 주행으로 실제 렌더 프레임, 바퀴 접촉과 회전 방향, 카메라 시야 확인.
3. 교사 주행으로 바깥 순환로와 가운데 교차로 회전의 이탈·도로 여유 확인.
4. 카메라 높이/각도와 차량 치수·질량·마찰·PWM 속도를 실차와 보정.
5. 무작위화 데이터를 충분히 수집한 후 별도 CUDA 환경에서 학습.
6. 학습에 사용하지 않은 시드·스트레스 조건·실차 영상으로 성능 측정.
7. 구현한 검출 추적·거리·교차로·미션 통합을 RTX에서 실행하고 인식률·미션 전체 성공률을 평가.

현재는 실제 RTX 시뮬레이션 완주나 강건한 모델의 완성을 확인한 상태가 아니다.
